# Security Policy

## Reporting a Vulnerability

If you find a security vulnerability in a StellarYard contract, please report it responsibly.

**Do NOT open a public GitHub issue for security vulnerabilities.**

Instead, please email: **security@stellaryard.dev**

Include:

- Contract and function affected
- Description of the vulnerability
- Steps to reproduce (a failing test is ideal)
- Potential impact
- Suggested fix (if any)

## Response Timeline

- **Acknowledgment**: Within 48 hours
- **Initial assessment**: Within 1 week
- **Fix or mitigation**: Depends on severity, typically within 2 weeks

## Audit Status

**These contracts are unaudited.** They have unit tests and CI coverage, which
is not the same as an audit. Do not deploy them to hold real value, and do not
present them as production-ready in any integration.

If an audit changes this statement, update this section with the auditor, date,
and scope.

## Scope

- Smart contracts under `contracts/`
- The workspace build configuration (`Cargo.toml`, release profile)
- The CI workflow that builds and tests them

## Out of Scope

- `stellaryard-core`, `stellaryard-cli`, `stellaryard-dashboard` — report against those repositories
- The Stellar network protocol and Horizon/Soroban RPC — report to the Stellar Development Foundation
- Findings that require a compromised host machine or leaked private key
- The placeholder test keypairs generated by core for local networks

## Key Security Considerations

### Authorization

Every state-changing entry point must call `require_auth()` for the address
that owns the right being exercised. A PR that removes or weakens an auth
check is a security regression, not a refactor.

### Integer Behavior

The release profile enables `overflow-checks`. Any use of `wrapping_*`,
`saturating_*`, or raw arithmetic on user-controlled values needs a comment
explaining why it is safe.

### Storage and TTL

Persistent entries expire if their TTL is not extended. A mutation that writes
without extending TTL can silently lose state — include `extend_ttl` on every
write path.

### Event Integrity

Events are how off-chain systems reconcile state. Do not emit an event for an
operation that did not happen, and do not omit one for an operation that did.

## Disclosure Policy

We follow responsible disclosure. We will:

- Credit reporters (unless they prefer anonymity)
- Not pursue legal action for good-faith security research
- Work with reporters on disclosure timing
